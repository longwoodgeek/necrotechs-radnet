# Captain's Log v0.4

A local, interactive archival logbook built on the existing Python SQLite event journal.
**History is amended, never overwritten by the log service.** This is experimental local
software, with no authentication, authorization, secure clock, federation, or network I/O.
It does not change SharkDeck, Reticulum, LXMF, NomadNet, radio interfaces, or isolation settings.

## Use

From the repository, launch a separate validation journal:

```bash
python3 -m radnet --db radnet-v04-validation.sqlite3 terminal --plain
```

Select `[3] CAPTAIN'S LOG`. The log menu provides:

- `[1] Browse`: latest revision of each entry, newest local receipt first.
- `[2] Create`: unverified operator label, title, body, optional claimed time, source and uncertainty.
- `[3] History`: enter the full original entry ID; revisions appear in local receipt order.
- `[4] Search`: case-insensitive literal substring search of title, body, operator and correction
  reason across **all revisions**, including superseded originals. No SQL expressions or shell commands.
- `[5] Export`: enter a **new** local filename. Export is JSON, not a network upload.
- `[6] Correct`: enter the original entry ID and latest event ID from history, then the full
  replacement text and a reason. An outdated event ID is rejected; reload history and review it.
- `[0] Return`: leave the submenu. EOF or Ctrl-C exits without saving a partially entered record.

Browse, history and search display ten records per page: `>` next, `<` previous, `0` return.
IDs are complete SHA-256 strings; they are identifiers, not identity credentials.
Each correction is a full snapshot and has its own operator/time metadata. Blank time metadata
on a correction does **not** silently inherit the original's claims.

Example claimed time: `2026-11-13T12:30:00-05:00`. Use an explicit UTC offset and `T` separator.
Time source could be `operator watch` or `handwritten notebook`; uncertainty could be
`approximately five minutes` or `unknown`. These are operator statements, not measurements
verified by RadNet. Blank claimed time means no occurrence-time claim is supplied.

## Event and provenance model

No table migration or replacement database is required. Existing `message.create`, `board.create`
and `board.message` events remain intact. New events use the existing `events` table and hash scheme:

| Field | Meaning |
|---|---|
| Envelope `kind` | `log.create` or `log.correct` |
| Envelope `schema` | Existing journal envelope schema 1 |
| Envelope `author` | Unverified operator-supplied label; never an authenticated identity |
| Envelope `parents` | Empty for originals; exactly the previous revision ID for corrections |
| Envelope `local_seq`, table `received_seq` | Application-assigned local receipt ordering, validated for agreement |
| JSON body `schema` | Captain's Log payload schema 1 |
| `entry_id`, `previous` | Both null for originals; original ID and preceding revision ID for corrections |
| `title`, `body`, `reason` | Complete revision text; reason required for corrections |
| `claimed_time` | Operator-supplied ISO 8601 occurrence-time claim, or null |
| `time_source`, `uncertainty` | Bounded operator descriptions; defaults `not supplied`, `unknown` |
| `receipt.time` | UTC-formatted time sampled from this host when appending |
| `receipt.source`, `receipt.uncertainty` | Always `local_system_clock_unverified`, `unknown` |
| `provenance` | `local_terminal_unverified_operator`, identifying this local recording path |

Receipt sequence and clock fields are generated by the local application rather than accepted
from operator prompts. This gives them a different provenance from claimed operator time;
it does **not** make them secure or independently trusted. The host clock can be wrong, move
backwards or be changed. Receipt order does not prove occurrence order, causality or UTC accuracy.
An operator-entered source such as `GNSS` does not establish a verified GNSS timestamp.

The service starts an SQLite immediate transaction before checking the latest revision and
appending a correction. Two concurrent corrections against the same predecessor cannot both
succeed. Original rows are never updated or deleted by this service. There are no database-level
immutability guarantees against another program or someone editing SQLite directly. Hashes are
not signatures, do not authenticate operators or timestamps, and cannot prove completeness:
records can be removed or replaced by someone with database access. No tamper-proof claims.

Reads validate content hashes, payloads, local sequence agreement and correction links before
projecting the log. Detected damage rejects the operation instead of presenting a partial valid
archive. Keep the database for diagnosis; the log does not attempt automatic repair.

## Bounds and display

Operator labels: 32 characters; title: 100; body: 4000; correction reason: 500; claimed time: 64;
time source/uncertainty: 200 each; search: 200; export filename in the terminal: 1024.
Required fields reject empty or whitespace-only text. Text rejects Unicode control/format
characters except newline and tab, and strips leading/trailing whitespace at recording time.
The terminal currently captures one line per field. All displayed archive fields are sanitized
again, removing control/format characters, including escape sequences and bidirectional controls.
Stored text and exported envelopes are not modified by display sanitization. Export JSON escapes
non-ASCII/control characters. Page numbers are 1..10000. Reads currently scan/validate the local
journal in memory; this is a small local prototype, not a large archive indexing service.

## Non-destructive export and preservation

Export contains original envelopes, IDs, parsed payloads, local receipt sequences and a notice
about unauthenticated identity/time. It is a snapshot of Captain's Log events only, in receipt
order, including every correction. It is **not** a complete SQLite backup or an import feature.
The exporter never updates/deletes journal events, opens the destination with exclusive creation,
and refuses existing files, symlinks, and the active database/SQLite sidecar names, even when
those names do not yet exist. Existing hard links are also refused. A write/storage failure can
leave an incomplete new export file; retain the journal and retry with a different filename.
Filesystem access by other hostile processes is outside this prototype's security model.

Choose a private directory outside the repository for exports; logs may contain private data.
For a complete backup of a live journal, use SQLite's backup facility or stop all writers and
preserve the database consistently with its sidecars. Do not copy only the database while an
active writer may still have records in WAL. Never deploy this validation run onto SharkDeck
or change station interfaces merely to test the log.

## MacBook validation

Fetch the feature branch (review local changes before switching):

```bash
git fetch origin
```

```bash
git switch feature/captains-log-v0.4
```

```bash
python3 -m unittest discover -s tests -v
```

```bash
python3 -m compileall -q radnet tests
```

```bash
python3 -m radnet --db radnet-v04-validation.sqlite3 terminal --plain
```

Create an entry; browse it; copy its original ID; correct it with a reason using the latest event
ID; view both revisions; search for text present only in the original; export to a new private
filename. Repeat export to the same filename and confirm rejection. Restart the terminal and
confirm both revisions persist. Exercise boards in the same validation database and confirm
posts/replies still work. Then check the journal:

```bash
python3 -m radnet --db radnet-v04-validation.sqlite3 verify
```

Automated development validation: Python 3.14.6 on the Mac host, 48 tests passed (26 existing,
22 new), syntax compilation and `git diff --check` passed. Coverage includes concurrent/stale
corrections, preservation, provenance, bounds, unsafe display text, damaged journals, export
collisions/sidecars, interruptions, scripted menu flow and a socket-blocked local session.
These are local software tests; human MacBook acceptance and live SharkDeck/radio validation
are not claimed. Keep the PR draft until review and acceptance; no merge is performed here.
